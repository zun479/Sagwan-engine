# 거버넌스와 정직한 한계

## 역할

- **슈퍼 운영자 (1명):** 클라우드·도메인 비용을 내는 '지갑'. 영리 전환 시 수익도 귀속.
- **운영자 (N명):** 콘텐츠·커뮤니티 실무. 인프라 책임 없음.

## 합의 규칙

- 신규 운영자 임명: 슈퍼만 발의, 기존 활성 운영자 **전원** 찬성.
- 해임: 즉시 불가. 7일 유예 + 나머지 운영자 전원 동의. 30일 이상 미접속 운영자는 정족수에서 제외.
- 라이선스 모드 변경: 슈퍼 발의 + 운영자 전원 동의 + 14일 사전 예고 배너.
- 슈퍼 운영자 인수인계: 운영자 콘솔에서 지목 → 인수자가 인계 자료 확인 후 비밀번호를 다시 입력해 수락 → 역할 맞교환 → 인프라 이전 체크리스트.

## 감사 로그의 한계 (중요)

슈퍼 운영자는 데이터베이스(D1)에 직접 접근할 수 있습니다. 그래서 **슈퍼 운영자는 기술적으로 전능합니다.**
감사 로그는 위변조를 *불가능하게* 만드는 장치가 아니라, 위변조를 *드러나게* 만드는 사회적 견제 장치입니다.

보강 장치:

1. **해시 체인.** 각 로그 행은 직전 행의 해시를 포함한 SHA-256 해시를 가집니다. 중간의 한 줄을 지우거나 고치면 그 뒤 체인이 모두 깨집니다.
2. **공개 검증.** 감사 리스트 화면에 최신 해시를 표시하고, 운영자 누구나 체인 검증을 실행할 수 있습니다.
3. **외부 사본.** 주기적으로 체인 덤프를 공개 저장소 경로에 내보냅니다. 운영자는 최신 해시를 따로 적어 두는 것만으로도 나중의 위변조를 알아챌 수 있습니다.

그래도 슈퍼 운영자가 체인 전체를 처음부터 다시 만드는 것은 막을 수 없습니다. 외부 사본과 운영자들의 기록이 마지막 방어선입니다.

## 비밀번호 재설정

엔진은 메일 서버를 두지 않습니다(운영비 0원 원칙).

- 운영자가 비밀번호를 잊으면 **슈퍼 운영자가 콘솔에서 1회용 재설정 링크(24시간, 1회 사용)를 만들어** 디스코드 등으로 직접 전달합니다.
- 슈퍼 운영자 본인이 잊으면 Wiki Hub(또는 `scripts/hash-password.mjs` + `wrangler d1 execute`)로 비밀번호를 다시 씁니다. 클라우드 계정에 접근할 수 있는 사람만 가능합니다. **인프라 소유 = 최종 신원.**

## 백업

슈퍼 운영자 콘솔의 [백업 받기]는 위키 데이터를 JSON으로 내려줍니다. 다음 테이블은 **포함하지 않습니다:**
`managers`, `manager_proposals`, `manager_votes`, `password_reset_tokens`, `sessions`.
감사 로그는 운영자 ID를 번호로만 남깁니다.
